# NEERGUARD

NEERGUARD is an Android-first Expo app for screening selected water-quality indicators with an IoT device. The existing ESP32/PlatformIO firmware remains in `src/` and `include/`; the mobile app is an additional project at the repository root.

## What the app reports

- Overview of device/API connectivity, latest sample time, configured-range status, measurements, and reported events.
- A drinkability screening summary that distinguishes missing/stale data, configured-range warnings, and readings within the configured ranges without claiming that water is safe to drink.
- Measurement cards for pH, turbidity (NTU), total dissolved solids (ppm), and temperature.
- Time-filtered charts and timestamped reading history, preserving gaps for missing/invalid values.
- Active and resolved API events with values, configured references, timestamps, and suggested investigations.
- Device troubleshooting, calibration guidance, editable screening ranges, temperature display units, and history-display retention.
- System light/dark theme, accessible controls, explicit loading/error/empty states, and a persistent **DEMO MODE** notice when sample data is selected.

The app screens selected indicators only. It cannot determine whether water is safe to drink or detect every pathogen or chemical contaminant. “Within configured ranges” is not a drinking-water safety claim. Default screening ranges are editable examples, not regulatory guidance.

## Install and run on Android

Requirements: Node.js supported by the selected Expo SDK, npm, and either an Android device with Expo Go or an Android emulator.

```powershell
npm install
npm start
```

In the Expo terminal, press `a` to open an installed Android emulator, or scan the QR code with Expo Go on a device on the same network. Alternatively run:

```powershell
npm run android
```

For a browser preview, run:

```powershell
npx expo start --web
```

An Android emulator cannot reach a service on the development computer via `localhost`; use `http://10.0.2.2:<port>` for the host machine. A physical phone should use the computer's reachable LAN address.

## Demo and API modes

The app defaults to clearly labelled **DEMO MODE**. Its illustrative values are generated by the separate `DemoDataProvider`; they are not sensor readings and do not imply a connected device. The demo reports calibration as unconfirmed and includes no alert events.

To select the real API at startup, set Expo public environment variables before starting Metro:

```dotenv
EXPO_PUBLIC_DATA_MODE=api
EXPO_PUBLIC_API_BASE_URL=http://10.0.2.2:3000
```

Copy `.env.example` to `.env.local` and edit the URL, or enter a base URL and select **Live API** in Settings. Settings selected in the app are saved locally and override the environment defaults. Use `https://` for a deployed service; never put credentials or secrets in `EXPO_PUBLIC_*` variables because they are bundled into the client.

The API adapter calls all five documented endpoints. A failed request, non-2xx response, or malformed required API object is shown as an error; it never falls back to demo values. Missing/malformed individual readings remain null and invalid. Refresh retries the request. Reading age is checked against a 15-minute staleness window.

## Backend contract

All endpoints return JSON. API base URLs must include the scheme and host, but not `/api`.

### `GET /api/health`

```json
{
  "status": "ok",
  "checkedAt": "2026-03-01T10:00:00.000Z",
  "deviceConnected": true
}
```

### `GET /api/device`

```json
{
  "deviceId": "NG-001",
  "firmwareVersion": "0.1.0",
  "connected": true,
  "apiConnected": true,
  "lastContact": "2026-03-01T09:59:00.000Z",
  "configured": true
}
```

`lastContact` may be `null`. Connection and configuration booleans are required.

### `GET /api/readings/latest`

Returns `null` when the service has no latest reading, or one record:

```json
{
  "id": "reading-001",
  "timestamp": "2026-03-01T09:59:00.000Z",
  "measurements": {
    "ph": {
      "value": 7.1,
      "unit": "pH",
      "valid": true,
      "calibrated": false,
      "timestamp": "2026-03-01T09:59:00.000Z",
      "rawValue": 2.44
    },
    "turbidity": {
      "value": 2.4,
      "unit": "NTU",
      "valid": true,
      "calibrated": false,
      "timestamp": "2026-03-01T09:59:00.000Z"
    },
    "tds": {
      "value": 286,
      "unit": "ppm",
      "valid": true,
      "calibrated": false,
      "timestamp": "2026-03-01T09:59:00.000Z"
    },
    "temperature": {
      "value": null,
      "unit": "°C",
      "valid": false,
      "calibrated": false,
      "timestamp": "2026-03-01T09:59:00.000Z",
      "error": "Sensor not installed"
    }
  }
}
```

Each measurement has a nullable numeric `value`, string `unit`, boolean `valid` and `calibrated`, and ISO-8601 `timestamp`. `rawValue` and `error` are optional. A value is treated as valid only when it is a finite number and `valid` is `true`. Omitted/malformed measurements are rendered as unavailable, never as zero. The app expects temperatures in °C from the API; the user can choose °F for display.

### `GET /api/readings`

Returns an array of the same records, or `{ "readings": [...] }`. Records should include stable IDs and ISO-8601 timestamps. The app preserves invalid samples as chart gaps.

### `GET /api/events`

Returns an array of events, or `{ "events": [...] }`:

```json
{
  "events": [
    {
      "id": "event-001",
      "parameter": "ph",
      "measuredValue": 8.7,
      "unit": "pH",
      "reference": "configured maximum 8.5",
      "timestamp": "2026-03-01T09:59:00.000Z",
      "active": true,
      "priority": "warning",
      "suggestedInvestigation": "Check the probe condition and confirm the sample using an appropriate validated method."
    }
  ]
}
```

`parameter` is one of `ph`, `turbidity`, `tds`, or `temperature`; `priority` is `warning` or `high`. The API is responsible for emitting suggested investigations and for resolving/retaining events.

## Connect the ESP32 directly

The firmware exposes the app's API on the ESP32's local Wi-Fi network. Copy `include/secrets.example.h` to `include/secrets.h`, set the Wi-Fi name/password, build and upload with PlatformIO, then read the ESP32 IP address in the serial monitor. In app Settings, enter `http://<device-ip>` as the API base URL and select **Live API**. The phone and device must be on the same reachable network; do not expose this unauthenticated HTTP API to the public internet.

The firmware reports pH, turbidity, and TDS. It advertises those three as supported, so the app omits temperature and does not block screening on its absence. The sample timestamp uses network time; readings remain unavailable/stale until the device can synchronize its clock. Sensor calibration and the configured ranges still need to be verified for your hardware and local guidance.

The firmware keeps the latest sample in memory and returns that sample as its available history. It reports no event records. API compatibility does not imply the measurements prove water is safe to drink.

In Live API mode, the app refreshes the device data every 30 seconds; pull down on a screen to refresh immediately.

The pH and TDS sensors must be wired to separate ADC pins. The example uses GPIO32 for pH and GPIO35 for TDS; update the pin definitions in `include/secrets.h` to match the actual wiring. The firmware fails to compile if both are configured to the same pin.
